# Telegram → Codex, Windows

10 октября 2026: ответы адаптированы для телефона: вывод сверху,
пронумерованные варианты, отдельные строки цены, источника и условий.
Инструкции запрещают Markdown-таблицы и сплошное выделение абзацев.
Если модель всё же вернула таблицу, formatting.py превращает корректные
строки в блоки с названиями полей, сохраняя факты и ссылки. Таблицы в коде
и таблицы с неверным количеством колонок остаются буквальными. Заголовки
становятся жирными. Длинные сообщения делятся по абзацам/строкам, когда
это возможно, с сохранением текста и entities. Проверки: 52 теста PASS.

10 октября 2026: пересланные подряд сообщения собираются в одну durable
задачу после 5 секунд тишины. Сохраняются авторы, порядок, цитируемые ответы
и все поддерживаемые вложения; пояснение владельца сразу после пересылок
присоединяется к пакету. Во время другой работы пересылки копятся отдельно,
а не уходят по одной в turn/steer. Цитаты не управляют командами моста.
Под живым ответом появляется кнопка «⏹ Стоп», привязанная к текущей задаче.
Кнопка, /stop и «стоп» прерывают работу, отменяют queued/collecting задачи
и поздние уточнения. Новая явная задача снова запускает работу; отменённые
задачи автоматически не повторяются. Кнопка удаляется из итогового ответа.
Выполненные до остановки действия не откатываются.

10 октября 2026: исправлена отправка Markdown как буквального текста.
Общий formatting.py переводит жирный, курсив, зачёркивание, код и HTTP(S)
ссылки в Telegram entities; HTML модели остаётся обычным текстом. Живые
sendMessage/editMessageText и итоговые части используют этот обработчик.
Длинные ответы делятся после разбора с сохранением форматирования; смещения
и длины считаются в UTF-16, включая эмодзи. Незавершённая разметка в потоке
остаётся буквальной до получения закрывающих символов. Полный Markdown
(таблицы и прочая блочная разметка) не реализован.
Проверки: 37 тестов PASS; отключение разбора выявлено 7 проверками регрессии.
Команда: `python -m unittest discover -s deploy/telegram-codex -p 'test_*.py'`.

Исходящие файлы: модель указывает `MEDIA: абсолютный_путь` в конце ответа.
Мост проверяет существование файла внутри CodexWorkspace и отправляет его
как sendDocument (изображения также файлом, без изменения качества). Файлы
вне рабочей папки и служебные secrets/.env запрещены; максимум 50 МБ.
Локальные Markdown-ссылки поддержаны для совместимости; пути и MEDIA строки
убираются из итогового сообщения и живого превью. Модель не получает токен.
Таблица outgoing_files сохраняет SHA256, status и Telegram message_id.
Подтверждённые отправки одной задачи не дублируются; unknown/sending не
повторяются автоматически. История jobs и авторизация остаются прежними.

Входящие вложения: авторизованный владелец может прислать фото, документ,
voice/audio. Подпись сохраняется с задачей; file_id и metadata записываются
в отдельную таблицу attachments той же локальной SQLite транзакцией с jobs.
Файлы до 20 МБ сохраняются в `CodexWorkspace/TelegramInbox` с именем по
update_id; имя отправителя не используется как путь. Повтор update_id не
создаёт ещё одну задачу. Внешние адреса, обходы каталога и symlink запрещены.
Это не миграция рабочей CRM БД: старая jobs и история не меняются.

Фото идут в localImage app-server; документы доступны агенту по локальному
пути. Для PDF/Word/Excel используется существующий bundled Python с pypdf,
pdfplumber, pypdfium2, python-docx и openpyxl — новые библиотеки не ставятся.
Голосовые передаются SSH на Mac mini в codex-telegram-audio и распознаются
существующим Hermes local STT через transcribe_remote.py. Расшифровка идёт
в задачу, без отдельного эха в Telegram. Ошибка Mac/STT не блокирует текст.
Доступ к Mac mini нужен только для голосовых; новые ключи и провайдеры не
добавляются. Старые отвергнутые вложения нужно отправить повторно.
Проверки: 15 тестов PASS; реальный localImage определил красный квадрат,
Codex прочитал 73519 из текстового файла; Windows → SSH → Hermes local STT

после включения ещё не проверялся. Новые пакеты и модель не устанавливались.
Резерв: backup-attachments-20261009. Лимит входящего файла 20 МБ соответствует

Живой ответ: `streaming.py` читает публичные `item/agentMessage/delta`
из Codex app-server. Первые слова создают одно сообщение, дальнейшие порции
редактируют его не чаще раза в 2 секунды. Итог заменяет промежуточный текст.
Reasoning, команды, вывод инструментов и ошибки протокола в превью не идут.
Неизвестную отправку не повторяем; неудачное редактирование не создаёт дубль.
Сохранённый thread_id продолжается через thread/resume; модель и разрешения
не расширяются. Проверено: 8 тестов PASS, реальный поток 29 порций,
Telegram message_id 24 — одна отправка и одно финальное редактирование.
Bundled Windows Python использует safe_path: bridge.py явно добавляет свою
установленную папку для импорта streaming.py, без изменения настроек Python.

Получение задачи не сопровождается подтверждением «Принял задачу»:
бот сохраняет её в очередь и присылает результат. Команды /start и /status,
ошибки и пояснения для неподдерживаемых вложений продолжают отвечать.

Отдельный постоянный универсальный разговор Codex app-server; не подключается
к активному окну desktop-чата. Только текстовые личные сообщения владельца.
Владелец привязывается одноразовым кодом с ограниченным сроком.

Общая рабочая папка: `C:/Users/UserVik/CodexWorkspace`. Путь к CRM передаётся
через `--crm` и список разрешённых рабочих корней; агент читает её AGENTS.md, когда задача касается
CRM. Обычные вопросы, тексты и другие задачи не требуют исследования CRM.
Для начала и продолжения разговора cwd устанавливается явно в RPC;
общая папка не обязана быть Git-репозиторием. Другие каталоги автоматически
не получают разрешения на запись. Привязка владельца и история сохраняются.

Токен, SQLite, ответы и события хранятся вне Git в защищённой папке
`C:/Users/UserVik/.codex/secrets/telegram-codex`. Не выводить содержимое токена.
Новых зависимостей нет. Один процесс защищён OS-lock. Telegram update_id
исключает повтор задач; оборванные задачи не перезапускаются автоматически.
Неизвестная доставка не повторяется вслепую. Existing webhook не заменяется.

Codex использует текущую конфигурацию модели и workspace-write, без обхода
разрешений. Для ограниченных действий возвращает причину остановки.
Компьютер должен работать; автозапуск установлен при входе в Windows. Во время работы
нельзя параллельно править те же файлы из другого разговора.

Проверка: `python deploy/telegram-codex/test_bridge.py`.

нельзя объявлять проверенной сквозную передачу пользовательской задачи.

## Управление и восстановление — 9 октября 2026

Обработка задачи идёт в одном отдельном потоке; Telegram продолжает читать сообщения.
SQLite-соединение принадлежит своему потоку. `/stop` или «стоп» прерывают работу.
Обычный текст во время работы уточняет текущую задачу, вложения остаются следующей
задачей. Позднее непрочитанное уточнение сохраняется в очереди.
Вопросы app-server отвечаются обычным сообщением; отдельное разрешение на команду/файл
выдаётся только через `/approve`, отказ — `/deny` или другой ответ. Разрешение не
распространяется на сессию, глобальную политику или другое действие. Другие виды
интерактивных запросов пока завершаются безопасным отказом.

`/resume` снимает локальную остановку после ошибки и позволяет дать продолжение в
сохранённом разговоре. Прерванные задания и неизвестные отправки автоматически не
повторяются. `supervisor.py` запускается задачей Windows `PM Telegram Codex` при входе:
один supervisor и один gateway защищены OS locks. Восстановление ограничено тремя
запусками за час. 401, конфликт потребителей или существующий webhook останавливают
восстановление. Память проектов — `CodexWorkspace/PROJECTS.md`, без ключей и паролей.

Проверки: 24 целевых теста PASS. Реальная app-server-проба `/stop` получила
`turn/completed: interrupted`. Генератор создал PNG, 1 023 917 байт (imageGeneration).
CUA-инструмент доступен, но список браузеров пуст: Edge и встроенный браузер ответили
«Browser is not available». В desktop CUA также обнаружена ошибка создания kernel
assets (os error 3). Управление браузером и скриншоты пока не подтверждены: требуется
восстановление/подключение браузерного runtime. Перезагрузка Windows не выполнялась;
проверены регистрация задания, запуск и восстановление gateway после остановки.
Резерв runtime и SQLite: `backup-controls-*` в защищённой папке моста.

Предпросмотр Telegram: интервал правок уменьшен с 2 до 1 секунды. Первый текст
публикуется сразу; фактическая частота зависит от появления текста и сети.
24 целевые проверки PASS. Активное задание не прерывается при установке.

Живой таймер: при начале задачи сразу публикуется «⏳ Работаю · 0:00».
Таймер обновляется отдельным потоком раз в секунду, включая подготовку вложения
и периоды без публичного текста. Публичный текст получает строку с прошедшим
временем; финал заменяет то же сообщение и выключает таймер. RLock сериализует
публикацию токенов и таймера. 25 проверок PASS; реальная проба Telegram
(message_id 54) подтвердила начальную публикацию, правки и финальную замену.
Резерв до установки: backup-timer-* в защищённой папке моста.

Разрешения исправлены: реальный запрос app-server содержит кнопки Telegram
«Разрешить»/«Отклонить», с одноразовым токеном текущего запроса. Callback
принимается только от владельца в личном чате; старая кнопка недействительна.
Обычный текст больше не превращается в отказ. /approve без ожидающего запроса
не отправляется модели; отказ использует cancel, если decline не предложен
сервером. 28 тестов PASS. Журнал подтвердил исходную причину: первое /approve
разрешило SSH, следующий обычный ответ ошибочно отклонил второй запрос.
Код не расширяет постоянные permissions и не возобновляет старый прогон.
Резерв runtime: backup-approval-buttons-* в защищённой папке.

Старт при отключённом прокси: getWebhookInfo теперь ждёт восстановления
транспортного соединения с паузой 10 секунд вместо завершения процесса.
401, отклонение API и существующий webhook не повторяются. 29 проверок PASS.
После восстановления локального прокси Telegram getMe подтверждён; gateway
возобновлён без переигрывания заданий или повторных отправок.
