# Доступ к Автоботу через CRM

`autobot-access.conf` подключается внутри HTTPS server. `autobot-protected.conf` — внутри всех location, которые отдают страницы, документы или пользовательские API Автобота. Nginx сначала вызывает внутренний `/_pmbi_autobot_access`, который проверяет существующую сессию через `GET /api/autobot/access-check` CRM. Тело исходного запроса в проверку не передаётся. Ошибка проверки закрывает доступ.

Права повторяют `user_can_access_autobot`: главный администратор, администратор, директор, прораб; учитываются дополнительные роли. Анонимный запрос получает 401, роль без доступа — 403. Сессии, пользователи, пароли и токены не копируются в Автобот. Проверяются Origin/Sec-Fetch-Site исходного браузерного запроса; HTTPS-схема передаётся в проверку. В CRM должен быть верный `PMBI_PUBLIC_BASE_URL` либо настроенное доверие к своему reverse proxy.

Обычные адреса `/autobot/…`, `/estimates`, `/tenders`, `/merge-report`, `/research` и группа пользовательских API защищены. Объявленные CSS и embed bridge остаются публичными. `/api/agent-market/v1/*` через CRM и прежний `/autobot/api/agent-market/v1/*` сохраняют отдельную Bearer-проверку исполнителя; все пять Flask-обработчиков проверяют токен до работы. Префикс исполнителя не предоставляет обход к остальным страницам. Его прежние лимит загрузки и параметры proxy сохранены. Внутренний порт 8765 должен оставаться на loopback; проверка Nginx не заменяет ограничение сетевого доступа к нему.

Для существующей конфигурации используется `install_autobot_access.py`. Он принимает точный SHA-256 предварительно просмотренного файла, проверяет ожидаемую раскладку location, сохраняет остальные директивы и резервную копию. Файл заменяется атомарно; `nginx -t` выполняется до reload. При ошибке установки прежний файл восстанавливается. Повторное применение не добавляет второй слой include.

Порядок выпуска: backup CRM и Nginx → сборка/проверка образа CRM → обновление CRM с новым access-check → проверка endpoint → установка include и проверка/reload Nginx → контроль закрытых URL, worker API, публичной CRM и внутреннего health. Рабочую БД для проверки ролей не изменять.

Изолированные проверки: `test_autobot_access.py` проверяет роли/Origin/маршрут и преобразование конфигурации; `nginx_autobot_access_probe.py` запускает отдельный Nginx на свободном loopback-порту с синтетическими upstream, проверяет отказы, разрешённые роли, POST, alias, ошибку auth upstream и служебный токен. Он не использует рабочие данные или сессии.

Откат приложения должен сохранять endpoint проверки и файлы include: старая CRM без них приведёт к закрытому доступу в Автобот. Для исправления после опубликованной защиты предпочтителен совместимый выпуск. Не возвращать прежнюю публичную конфигурацию Nginx только ради открытия страниц. Архив прежней конфигурации нужен для диагностики и согласованного восстановления.
