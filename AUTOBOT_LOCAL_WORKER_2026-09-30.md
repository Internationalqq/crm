## План и наблюдаемое поведение

- Общая очередь, сметы и переписка остаются в CRM. Один запускаемый локально
  процесс использует HTTPS API очереди, SMTP/IMAP Mail.ru, обычные шаблоны.
  Браузерные профили Гули/Альберта не затрагиваются, модели не запускаются.
- Пакет работает на Windows и macOS; запуск/стоп/статус явные. Секреты лежат
  отдельно от репозитория в закрытом каталоге. Повторный запуск не создаёт
  второй процесс; после сна/перезапуска очередь продолжается без дублей.
- При неясном результате отправки автоматического повторения нет. Смена
  устройства не должна превращать неопределённую отправку в новое письмо.
  Штатные проверки lease, Message-ID и сохраняемый журнал остаются.
- Сначала SMTP/IMAP auth без отправки, затем проверка получения и очереди.
  Серверный почтовый процесс отключается только после проверки локального.
  Для контрольной отправки допустим только собственный уже подключённый ящик;
  поставщикам — авторизованные сообщения по реальным потребностям.
- Предыдущая задача полного подбора Волги сохраняется; исправление лимита
  300 в `febb081` включено в выпуск ниже. Поиску SMTP не нужен.

## Проверки и ограничения

Проверки: отдельный процесс не может занять тот же журнал; остановка штатная;
повторное открытие не сбрасывает секреты/очередь; сообщения не дублируются при
неопределённом результате; Windows настоящий запуск + изолированные buyer
tests; Linux candidate перед выпуском и прежние хеши рабочих данных.
macOS явно отмечается непроверенной, пока на нём не выполнен запуск.

Локальный SMTP устраняет зависимость отправки от закрытых портов VPS, но не
даёт иммунитета от жалоб/ограничений Mail.ru или условий хостинга. Компьютер
должен быть включён с доступом к сети. Не обещаем доставку по ответу SMTP 250.

Источники: [Mail.ru SMTP/IMAP](https://help.mail.ru/mail/login/mailer/),
[HOSTKEY сети](https://hostkey.ru/documentation/faq/network_settings/),
[HOSTKEY правила](https://hostkey.ru/documentation/general/site_rules/).
