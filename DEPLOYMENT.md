### Порядок выпуска

1. Сверить локальный diff, исходный commit сервера и чистоту его рабочего дерева. Провести подходящие проверки; для общего рефакторинга — `python tools/check_project.py --suite all` на изолированной копии.
2. Сохранить закрытую резервную копию вне web-каталогов: SQLite через online backup API, файлы `data`, `.env`, архив исходного commit и manifest. Проверить `PRAGMA integrity_check` и восстановление SQLite в отдельный файл; отдельно сравнить прежние нарушения внешних ключей. Существующие нарушения не исправлять удалением строк во время деплоя.
3. **До пересборки** сохранить прежний образ отдельным тегом `crm-crm:rollback-<commit>` и проверить этот тег через `docker image inspect`. Один ID из `docker inspect` контейнера недостаточен: после замены тега и удаления старого контейнера прежний образ может стать недоступен.
4. Сделать коммит и обычный push в `origin/main`. Для передачи на сервер можно использовать инкрементальный `git bundle` от подтверждённого серверного commit; проверить bundle и точный SHA после fetch. Не использовать force push, reset или замену всего каталога с рабочими данными.
5. Собрать образ из `git archive` нового commit в отдельном `/opt/crm-releases/<commit>/source`, пока старая CRM работает. Снова проверить исходную версию и чистоту checkout, затем выполнить fast-forward и `docker compose up -d --no-deps --no-build crm`. AutoBot для изменения CRM не перезапускается.
6. Проверить commit, HTTPS, API графика, отказ приватных API без входа, версии и содержимое JS/CSS, целостность SQLite и состояние AutoBot. Открыть изменённый сценарий в браузере. Если сборка обновила окружение Python, проверить образ в отдельном контейнере без рабочей БД, секретов и внешней сети. Сохранить образ выпуска тегом `crm-crm:release-<commit>`.
7. Обновить план и отчёт фактическими результатами. Отдельный коммит документации также отправить в GitHub и перенести fast-forward на сервер; перезапуск CRM для изменения только Markdown не нужен.

При ошибке запуска вернуть checkout к сохранённому commit без удаления истории, восстановить тег сохранённого образа и пересоздать только CRM. Автоматически откатывать рабочую БД нельзя: после резервной копии пользователи могли сохранить новые данные. Миграции требуют отдельного плана, согласованного с их конкретными последствиями.

## Локальный запуск

Теперь рабочий запуск идёт через backend:

```powershell
python backend\server.py
```

Или двойным кликом:

```text
start-site.cmd
```

После запуска открой:

```text
http://127.0.0.1:8080/login
```

## Первый администратор

При первом запуске backend создаст:

```text
login: admin
```

Пароль будет в файле:

```text
data/INITIAL_ADMIN.txt
```

После входа и создания реальных пользователей этот файл лучше удалить.

Не храните этот пароль как рабочий: смените его в профиле администратора,
удалите `data/INITIAL_ADMIN.txt` и задайте отдельный длинный пароль интеграции.

## Важно про workers.dev

Просто загрузить папку `deploy` на workers.dev теперь недостаточно для настоящего продукта.

Папка `deploy` — это frontend.  
Backend `backend/server.py` должен где-то запускаться.

Основной новый интерфейс теперь открывается по адресам:

```text
/app/projects
/app/dashboard
/app/daily-tasks
/app/warehouse
/app/schedule
/app/logs
/app/suppliers
/app/users
/app/companies
/app/autobot
```

Основная архитектура frontend теперь лежит в `frontend/`.

Варианты:

- локальный сервер для разработки;
- VPS;
- Docker;
- Render/Railway/Fly;
- позже Cloudflare Workers + D1, если хотим остаться в экосистеме Cloudflare.

## Что выгружать

Для полноценного backend-варианта нужно выгружать весь проект:

- `backend/`;
- `frontend/`;
- `deploy/robots.txt` и `deploy/_headers`, если они нужны для конкретного хостинга;
- `start-site.cmd` / команда запуска;
- документы проекта.

Папку `data/` не выгружать публично: там база и первичный пароль.

## Безопасный сетевой доступ

Docker по умолчанию публикует CRM только на `127.0.0.1`. Для внешнего доступа
ставьте перед приложением HTTPS reverse proxy, задайте HTTPS-адрес в
`PMBI_PUBLIC_BASE_URL` и включите `PMBI_FORCE_SECURE_COOKIES=1`. Не открывайте
порт `8080` в интернет без TLS: логины и cookie сессии пойдут открытым текстом.
