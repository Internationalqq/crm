# Условия участия в тендере

Версия 1, 15 сентября 2026. Это предварительные сценарии участия. Они не создают договорную выручку, утверждённую базу, обязательства или фактические записи объекта CRM.

## Поведение

В карточке тендера руководителю доступен блок «Условия участия». Базовый, осторожный и оптимистичный сценарии сохраняются независимо. Базовый можно явно взять за основу; коэффициенты изменения не подставляются. Доставка, накладные, резерв и налоги вводятся для каждого тендера, согласно решению пользователя.

Основные поля заданы в рублях без НДС. Допустимы неотрицательные суммы с двумя знаками после запятой; сервер преобразует их в целые копейки. Пустое поле остаётся `null`, явный ноль означает отсутствие расхода. НДС в предложении и расходах вводится отдельными суммами, без ставки по умолчанию; он не входит в остаток и его долю в выручке. Возвратное обеспечение не является расходом: в поле комиссий указывается стоимость гарантии/комиссия. Сроки платежей, возврат обеспечения и кассовый разрыв эта версия не рассчитывает.

Остаток = цена предложения без НДС − материалы − работы − техника − доставка − накладные − комиссии − финансирование − резерв − налоги кроме НДС. Он рассчитывается только при заполнении всех этих сумм, положительной цене предложения, указанном основании и подтверждении состава/налоговой базы. Проверка состава включает отсутствие повторного счёта материалов и техники внутри работ. Отрицательный результат сохраняется. Неизвестные значения и изменённые источники не дают готового итога. Пустой набор расходов не отображается как нулевая себестоимость.

Найденная AutoBot часть рынка показана справочно. Она не переносится в затраты автоматически, поскольку налоговая база, полнота и состав предложения поставщика требуют проверки. Пользователь подтверждает введённые условия; это не автоматический вывод об участии. Происхождение оценки фиксируется заметкой и снимком версии источников.

## Доступ и хранение

`backend/tender_scenarios.py` использует существующее разрешение экономики: `main_admin`, `admin`, `director`. Проверка выполняется до чтения тела, обращения к AutoBot и открытия хранилища. Прораб и остальные роли получают только ошибку; финансовый блок не создаётся в их DOM. Все ответы имеют `Cache-Control: no-store` через общий HTTP-сервер. Применяется общий запрет межсайтовых записей.

Новый файл `data/tender_scenarios.sqlite3` создаётся при первом разрешённом чтении/сохранении. Существующие БД и экономические таблицы не мигрируют. Каждая запись — неизменяемая версия с автором из сессии, бизнес-датой на момент операции, условиями и снимком источника. Запись выполняется в `BEGIN IMMEDIATE`; версия защищает от конкурентной замены, ключ операции — от повторной записи после потери ответа. При повторе с другим содержимым сервер возвращает конфликт.

Интерфейс показывает последние десять версий каждого сценария; более ранние записи остаются в SQLite. «Взять за основу» заполняет форму; последующее сохранение создаёт новую версию. При сетевом сбое поля остаются в форме, повтор использует тот же ключ. Закрытие/перезагрузка страницы не сохраняет несохранённые изменения.

## Границы API

CRM: `GET/POST /api/autobot/tenders/{id}/economics`; отдельный `POST .../economics/preview` рассчитывает введённое без записи. В записи обязательны имя сценария, ожидаемый номер версии, ключ операции и версия источника. Неизвестные поля отклоняются. API не принимает автора или готовую прибыль от клиента.

AutoBot: `GET /api/tenders/{id}/economics-source` отдаёт только справочную сводку и версию. Версия включает SHA256 использованных отчётов, манифестов, метаданные и текущую пригодность цен. Файлы проверяются до и после чтения. При изменении источников сохранённые условия доступны, но итог требует повторной сверки; отметки полноты/налоговой базы при принятии новых источников снимаются.

При недоступном AutoBot CRM сохраняет доступ к прежним условиям, но не выдаёт готовую прибыль и не принимает новую запись. Форма и CSS принадлежат CRM и загружаются в карточку AutoBot через существующий общий домен. Отдельный AutoBot без CRM не предоставляет этот редактор.

## Выпуск и откат

Сначала публикуется CRM с API и статическими файлами, затем AutoBot с источником и точкой подключения формы. Конфигурация Nginx не меняется. Проверка новых сценариев и запись демонстрационных сумм выполняются только на изолированной БД. На production проверяются образы, связь сервисов, доступ и целостность существующих БД.

Общие резервные копии должны включать новый SQLite через online backup, включая журнал версий. При откате оба образа возвращаются к сохранённым тегам; файл сценариев сохраняется и не используется старым кодом. Рабочие записи сценариев не удаляются для отката. Конкретные коммиты, backup и проверки — в `AUTOBOT_IMPLEMENTATION_2026-09-14.md`.
