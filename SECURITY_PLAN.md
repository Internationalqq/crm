# PM.bi — безопасность и авторизация

## Текущий статус

Проект переведён с frontend-demo авторизации на backend-авторизацию.

Теперь вход работает через Python backend:

- `backend/server.py`;
- SQLite база `data/pmbi.sqlite3`;
- страница входа `/login` из `frontend/templates/login.html`;
- основной frontend в `frontend/`;
- API:
  - `POST /api/auth/login`;
  - `POST /api/auth/logout`;
  - `GET /api/auth/me`;
  - `POST /api/admin/users`;
  - `GET /api/projects`;
  - `GET /api/projects/{id}/materials-summary`.

## Что защищено backend-ом

- Пароли не лежат в JavaScript.
- Пароли хешируются через PBKDF2-SHA256.
- Сессии хранятся в базе на сервере.
- В браузер кладётся только `HttpOnly` cookie.
- HTML-страницы отдаются только после проверки сессии.
- Доступ к HTML-страницам проверяется по роли.
- API возвращает данные только авторизованному пользователю.

## Первый вход

При первом запуске backend создаёт администратора:

```text
login: admin
```

Пароль создаётся автоматически и записывается в:

```text
data/INITIAL_ADMIN.txt
```

После создания реальных пользователей этот файл нужно удалить.

Если хочешь задать пароль сам при первом запуске:

```powershell
$env:PMBI_ADMIN_PASSWORD="сложный-пароль"
python backend\server.py
```

## Роли

### Директор

Полный доступ.

### Прораб

Доступ к объектам, задачам, графику, складу, закупкам, чатам и рабочей информации.

### Закупщик

Доступ к объектам, закупкам, поставкам, складу, поставщикам и рабочим чатам.

Не должен видеть внутреннюю прибыльность, если это скрыто.

### Заказчик

Доступ только к клиентской части:

- свои объекты;
- прогресс;
- график;
- открытые документы;
- чат с командой.

Не должен видеть:

- другие объекты;
- внутренний чат;
- маржу;
- закупочные цены;
- прибыльность;
- складовую внутреннюю кухню.

## Важное ограничение

Backend уже защищает страницы и API. Новый основной интерфейс лежит в `frontend/` и не тащит старые сохранённые HTML-страницы.

Для настоящего продукта все чувствительные данные нужно держать в backend/API:

- финансы;
- маржу;
- закупочные цены;
- склад;
- сметы;
- чаты;
- документы.

Тогда backend сможет не просто скрывать элементы, а вообще не отдавать запрещённые данные пользователю.

## Деплой

Просто залить папку `deploy` на workers.dev уже недостаточно для настоящей защиты, потому что это статический хостинг.

Для реального продукта backend должен запускаться отдельно:

- VPS;
- Docker;
- Render/Railway/Fly;
- любой сервер с Python 3.11+;
- либо позже переписать backend под Cloudflare Workers + D1.

Команда локального запуска:

```powershell
python backend\server.py
```
