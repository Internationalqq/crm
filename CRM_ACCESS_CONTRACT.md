# Доступ в CRM: действующий контракт

Сверено с кодом и проверками 12 сентября 2026 года. Это описание сохранённого поведения, а не разрешение расширять публичный доступ.

## Вход и публичное портфолио

- `/` без сессии перенаправляет в `/app/projects`; `/login` открывает форму входа. Выход удаляет серверную сессию и возвращает в публичное портфолио.
- Анонимный посетитель видит публичные сводки объектов, опубликованные отчёты и график производства. Финансовые поля, внутренние сведения об объекте, авторы и исходный ввод отчёта в эти ответы не входят.
- Точный перечень публичных API находится в `backend.auth.public_api_allowed`: только GET списка/сводки объекта, отчётов, графика, разрешённого просмотра вложения и `/api/auth/me`.
- Остальные API требуют аутентификации. Приватные страницы без сессии перенаправляют на вход с `next`. POST не получает права публичного читателя после предыдущего GET.
- Ошибочный токен Clerk и существующий аккаунт Clerk без выданного доступа сохраняют ошибку авторизации. Их нельзя молча заменять анонимным посетителем.

## Гость с учётной записью и заказчик

- Гость с выданными учётными данными видит только назначенные ему объекты. Его API ограничен `guest_api_allowed`: список, опубликованные отчёты, график и разрешённые фотографии, а также операции входа/выхода/сброса пароля. Прямой endpoint полной карточки не разрешён гостевым шлюзом.
- Заказчик видит назначенные объекты. Финансовые поля и внутренние отчёты исключаются сервером; обращение к чужому объекту запрещено. Остальные действующие права заказчика сохраняются, их нельзя выводить из гостевой роли.
- Для сотрудников доступ к объектам и финансовым/закупочным сведениям проверяют серверные функции `user_can_access_project`, `user_can_view_project_economics`, `user_can_view_procurement_prices` и проверки конкретной операции.
- Видимость вкладок — дополнительное удобство интерфейса. Она не заменяет серверную проверку. Мобильный выбор раздела и обычные вкладки используют одну политику; прямой переход к запрещённой вкладке возвращает разрешённую начальную вкладку.

## Публикация фотографий

Для публичного посетителя, гостя и заказчика фотография доступна только при выполнении всех условий: отчёт опубликован, фотография опубликована, документ/связь/отчёт принадлежат одному объекту и сам объект доступен посетителю. Это относится к обложке, списку фотографий и скачиванию файла. Публичная фотография внутреннего отчёта не публикует отчёт косвенно.

## Проверки и ограничения

Оперативное выполнение (`progress-item`, `sections/.../bulk-complete`): гость и заказчик не изменяют его. Для работы требуется `user_can_manage_schedule`, для материала — `user_can_manage_suppliers`. Вид одиночной позиции определяется сохранённой строкой, а не полем `kind` запроса. Снабженец сохраняет доступ к материалам, но не может пометить работу материалом и изменить выполнение. Явный ID другого объекта, отсутствующей или удалённой позиции не запускает поиск по названию.

Создание ручного движения `stock-moves` также требует `user_can_manage_suppliers` и доступа к объекту; гость/заказчик запрещены. Ключ повтора ограничен проектом и автором. Повтор возвращает только ID прежней записи; изменение параметров под тем же ключом даёт 409. Общее удаление защищённых цен из JSON остаётся в `PMBIHandler.send_json`.

Поведенческие проверки: `tests/test_guest_access.py`, `tests/test_auth_request_cache.py`; проверки данных и финансов продолжают выполняться в остальных профильных наборах. Полный изолированный Python-прогон после исправлений: 441 тест, успешно.

Публичное портфолио всех объектов — существующий продуктовый контракт. Поле `guest_visible` не следует считать реализованным выключателем публикации всего объекта: изменение этого поведения требует отдельной миграции и проверки потребителей. Рабочие назначения, пользователи и данные в ходе проверки не менялись.
